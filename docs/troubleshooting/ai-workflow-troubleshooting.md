# AIワークフロー強制に関するトラブルシューティング

> Last Updated: 2026-08-24

このドキュメントは、AIアシスタント（エージェント）がプロジェクトの定めた「Issue起票および専用ブランチ作成」のワークフローを無視して直接ファイルを編集してしまう問題と、それを防ぐための仕組み（Hooks）についてまとめたものです。

## 背景と課題

AIアシスタントは、テキストベースのルール（`AGENTS.md` など）で「必ずルールを守れ」と指示されていても、ユーザーからの依頼が「ドキュメントの些細な修正」などの場合、手前のタスク達成を優先してルールを読み飛ばし（無視し）、直接ファイル編集を行ってしまう傾向（特性）があります。

いくらプロンプトのトーンを強くしても、この「LLMの気まぐれな読み飛ばし」を100%防ぐことはテキストの指示だけでは不可能です。

## 解決策：Hooksによる物理的なブロック

テキストによるお願い（プロンプト）ではなく、システム的な強制力を持つ仕組みとして、Antigravity（Geminiエージェント等）の **Hooks** 機能を活用します。

プロジェクトの `.agents/hooks.json` にて、ファイル編集やコマンド実行ツール（`replace_file_content`, `write_to_file`, `run_command` など）が呼び出される直前に（PreToolUse）、ワークフローを検査するシェルスクリプトをフックとして走らせるように構成されています。

現在導入されている主なガード機構：
1. **メインブランチ編集保護 (`enforce_workflow.mjs`)**: AIがルールを読み飛ばして編集ツールを呼び出そうとしても、現在のブランチが `main` であった場合はスクリプトがエラーを返し、物理的にツール実行がブロックされます。
2. **PRフォーマット違反ガード (`enforce_pr_format.mjs`)**: AIが `gh pr create` を直接実行した際、PRの本文（`--body` または `--body-file`）にテンプレートの必須キーワード（変更種別など）が含まれていない場合、コマンド実行をエラーにしてブロックします。

## 過去の失敗と教訓（Issue #39）

かつて、このHooksの仕組みを用意していたにも関わらず、AIが直接編集できてしまう事象が発生しました。

**原因**:
`.agents/hooks.json` に記載されていたスクリプトのパスが間違っていました。
- 誤: `"command": "node \"${CLAUDE_PROJECT_DIR:-..}/scripts/enforce_workflow.mjs\""`
- 正: `"command": "node \"${CLAUDE_PROJECT_DIR:-..}/.agents/scripts/enforce_workflow.mjs\""`

パスが間違っていたため、フック実行時に「ファイルが見つからない」状態となり、結果としてフックが機能不全に陥り、AIはそのまま編集ツールを実行できてしまっていました。

**教訓**:
1. AIのルール逸脱を防ぐ最も確実な方法は、プロンプトの強化だけでなく「物理的なブロックスクリプト（Hooks）」を併用すること。
2. Hooks を設定した際は、パスや実行権限が正しく設定されており、実際に「AIが違反した際にブロックされるか」をテストして動作確認をしておくことが非常に重要です。
