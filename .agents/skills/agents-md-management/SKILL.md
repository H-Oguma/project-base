# AGENTS.md Management Skill (監査・改善 & 知見反映)

このスキルは、Anthropic公式の `claude-md-management`（`claude-md-improver` および `/revise-claude-md`）のベストプラクティスに基づき、本プロジェクトの憲章である [`AGENTS.md`](../../../AGENTS.md) および `.agents/rules/` の**陳腐化（ドリフト）**と**肥大化（コンテキスト汚染）**を防ぐためのメンテナンス手順です。

ユーザーからの指示内容に応じて、以下の **2つのモード** のいずれか（または両方）を実行してください。

- **モードA：監査・改善モード (`Improver`)**
  - トリガー例：「`AGENTS.md` を診断・採点して」「ルールと実装のズレをチェックして」「`/agents-md audit`」
- **モードB：セッション知見の反映モード (`Revise`)**
  - トリガー例：「今回の学びをルールに反映して」「今のミスを再発防止ルールに追加して」「`/agents-md revise`」

---

## モードA：監査・改善モード (`Improver`)

現在のコードベースの実態と [`AGENTS.md`](../../../AGENTS.md)（および `.agents/rules/`）を比較監査し、100点満点でスコアリングした上で具体的な改善パッチを提案します。

### ステップ1：コードベース実態の調査
以下のファイル・構造を実際に読み取り、プロジェクトの「現在の正（Single Source of Truth）」を把握します。
1. **コマンド・スクリプト定義**: [`Makefile`](../../../Makefile)、[`package.json`](../../../package.json)、[`frontend/package.json`](../../../frontend/package.json)、[`backend/pyproject.toml`](../../../backend/pyproject.toml)
2. **ディレクトリ・ガードレール構造**: ルート直下のディレクトリ、`.githooks/`、`.agents/rules/`、`.agents/skills/`、`.agents/scripts/`
3. **対象ドキュメント**: [`AGENTS.md`](../../../AGENTS.md) および `.agents/rules/*.md`

### ステップ2：6軸での品質スコアリング（100点満点）
以下の評価基準に基づき、客観的に採点します。

| 評価軸 | 配点 | チェック項目 |
| :--- | :---: | :--- |
| **1. コマンドの正確性・網羅性** | 20点 | 記載されているビルド・テスト・Lint・検証コマンド（`make check` 等）が [`Makefile`](../../../Makefile) や [`package.json`](../../../package.json) の実態と完全一致しているか。 |
| **2. ディレクトリ構造の整合性** | 20点 | [`AGENTS.md`](../../../AGENTS.md) 内のディレクトリツリーに、存在しないパスや、新設された重要ディレクトリ・スキルの記載漏れがないか。 |
| **3. 技術スタック・環境の正確性** | 15点 | Python / FastAPI / React / Vite / Oxlint / Ruff などのツール構成や実行環境ルールが最新の実態と合致しているか。 |
| **4. 簡潔性・階層分離（肥大化防止）** | 20点 | [`AGENTS.md`](../../../AGENTS.md) が肥大化（目安：200行超）していないか。特定タスク固有の細かいルールが [`AGENTS.md`](../../../AGENTS.md) に混入せず、`.agents/rules/` や `.agents/skills/` に適切に分離（Progressive Disclosure）されているか。 |
| **5. ガードレール・ワークフロー整合性** | 15点 | `.githooks/` や `.agents/scripts/enforce_workflow.mjs` の実際のブロック条件と、ドキュメント上のワークフロー説明に矛盾がないか。 |
| **6. 鮮度・メタ情報** | 10点 | `Last Updated` の日付や参照リンク切れがないか。 |

**グレード判定目安**:
- **S (95〜100点)**: 完全に同期されており模範的な状態
- **A (85〜94点)**: 軽微な記述ズレのみで良好
- **B (70〜84点)**: 一部コマンドや構造の乖離あり（更新推奨）
- **C (69点以下)**: 重大な陳腐化または肥大化あり（要リファクタリング）

### ステップ3：監査レポートと改善案の提示
以下のフォーマットでユーザーに診断結果を報告し、改善が必要な場合は差分（または直接修正の提案）を提示します。

```markdown
## 📊 AGENTS.md 監査レポート
- **総合スコア**: XX / 100点（グレード: X）
- **各項目の内訳**:
  1. コマンドの正確性: XX / 20
  2. ディレクトリ構造: XX / 20
  3. 技術スタック: XX / 15
  4. 簡潔性・階層分離: XX / 20
  5. ガードレール整合性: XX / 15
  6. 鮮度・メタ情報: XX / 10

### 🔍 検出された課題・改善ポイント
- [課題1と具体的な修正案]
- [課題2と具体的な修正案]
```

## モードB：セッション知見の反映モード (`Revise`)

開発セッション中に判明した「ハマりポイント」「ユーザーからの軌道修正」「暗黙の了解」を抽出し、次回のセッション以降でAIが同じ失敗を繰り返さないようルールへ定着させます。

### ステップ1：セッションからの学びの抽出
直近の会話履歴や作業内容を振り返り、以下のいずれかに該当する知見を特定します。
1. **ユーザーからの指摘・修正**: AIが誤ったやり方をし、ユーザーが訂正した事項
2. **環境・ツールの罠**: テスト実行、Gitフック、依存関係などでエラーになり解決に試行錯誤した事項
3. **新たに合意した規約**: 設計方針、命名規則、テストの書き方などで新しく決まった事項

### ステップ2：配置先の自動振り分け（肥大化防止ルール ★最重要）
抽出した学びを**何でも無造作に [`AGENTS.md`](../../../AGENTS.md) に追記してはいけません**。コンテキストウィンドウの消費を抑えるため、以下の基準で配置先を決定します。

| 知見の種類 | 反映先ファイル | 判断基準 |
| :--- | :--- | :--- |
| **全タスク共通の絶対原則** | [`AGENTS.md`](../../../AGENTS.md) | すべての会話・すべてのサブエージェントが常に知っておくべき最上位ルール（数行以内に凝縮すること） |
| **特定領域の開発規約** | `.agents/rules/*.md` | PRフォーマット、TDD、設計書更新など、特定フェーズで参照すべきルール |
| **定型作業の手順改善** | `.agents/skills/<skill>/SKILL.md` | Issue起票（`issue`）、タスク開始（`task-init`）、PR作成（`create-pr`）等の手順そのものの改善 |
| **エラー解決・回避策** | `docs/troubleshooting/*.md` | 特定のエラーや環境トラブルの原因と対処法の記録 |

### ステップ3：ルールの更新と検証
1. 決定した配置先ファイルに対して、既存の文脈を壊さず簡潔な日本語でルールを追記・更新し、`Last Updated` の日付を最新化します。
2. 変更後、必要に応じて `make check` を実行し、リポジトリの検証が通ることを確認します。
3. ユーザーに「何を」「どのファイルに」「なぜ配置したか」を簡潔に報告します。
