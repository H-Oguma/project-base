# Instructions
このプロジェクトでは「設計書（ドキュメント）と実装の完全な同期」を最重要視しています。
AI（私）がコードの実装や変更を行う際は、以下のルールを**必ず**遵守すること。

- **設計書の更新義務**: 新しいAPIの追加、DBスキーマの変更、フロントエンドの主要コンポーネントの追加など、システムの実装に変更を加えた場合は、**必ず** `docs/architecture/system-design.md` （システム設計書）をセットで更新すること。
- **実装と設計の往復**: 実装を終えてから設計書を更新する、あるいは設計書を更新してから実装を行うこと。設計書が古い状態のままタスクを完了（エンドユーザーに報告）してはいけない。
- **記載すべき内容**:
  - バックエンド: 追加・変更したAPIエンドポイントのパス、メソッド、リクエスト/レスポンスの型、およびDBモデル（テーブル）の定義。
  - フロントエンド: 画面一覧、主要なコンポーネントと役割、状態管理のフロー。
  - インフラ: 起動方法や環境変数の追加などがあれば追記。
- **最終更新日の明記**: ドキュメントの信頼性を担保するため、更新したドキュメント（Markdownファイル）の冒頭（タイトルの直下）には必ず `> Last Updated: YYYY-MM-DD` またはバージョンを記載・更新すること。日付のない「最新」という言葉は使用しないこと。
