# Instructions

本プロジェクトはテスト駆動開発（TDD）および継続的インテグレーション（CI）を前提としています。AIがコードを記述・修正する際は、以下のルールを**絶対に遵守**すること。

- **テストの先行・並行実装**: 機能の追加やバグ修正を行う際は、対象となるロジックに対するテストコード（バックエンドなら `pytest`、フロントエンドなら `vitest`）を必ず実装すること。
- **オールグリーン（All Green）の必須**: 新しいコードをコミットまたはPull Requestにする前に、ローカル環境（またはコンテナ）でテストが100%通過することを確認しなければならない。
- **カバレッジの意識**: 正常系だけでなく、エラー時の挙動（異常系）についても適宜テストを記述すること。
- **CIとの連動**: 最終的にPRはGitHub Actionsによって自動テストされ、すべてパスしないとマージできない仕様になっている。ローカルでテストを省略してはならない。
