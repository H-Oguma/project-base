# Agent Orchestration & Definitions

本プロジェクトではコスト最適化と効率的なリソース管理を厳守する。
以下の5種類のサブエージェントを `define_subagent` で定義して使用し、タスクの性質に応じて最も安価なモデルを選択すること。

## コスト階層（安い順）

| モデル | コスト | 選定基準 |
|:--|:--|:--|
| `flash_lite` | 最安 | 単純なファイル読み取り、定型出力のみ |
| `flash` | 安価 | リサーチ・分析・レビュー・テスト実行（**最も頻用**） |
| `inherit` | 標準 | 複雑なコード生成・設計判断 |
| `pro` | 高価 | **ユーザーが明示的に指示した場合のみ使用可** |

## 1. サブエージェントの定義と使い分け

### 🔍 researcher（コードベースリサーチャー）
- **推奨モデル**: `flash`
- **書き込み/MCP**: なし（`enable_write_tools: false`, `enable_mcp_tools: false`）
- **役割**: コードベース調査、Web検索、影響範囲の確認。
- **システムプロンプトの指示**: 日本語で回答し、調査結果は箇条書きで構造化し、絶対パスを使用する。

### 🛠️ worker（実装ワーカー）
- **推奨モデル**: `inherit`（親と同じ）
- **書き込み/MCP**: あり（`enable_write_tools: true`, `enable_mcp_tools: true`）
- **役割**: コード実装、テスト作成、コマンド実行。
- **システムプロンプトの指示**: ルール（セキュリティ、TDD、ドキュメント）を遵守し、仮想環境・Dockerを使用する。並列作業可。

### 📋 reviewer（コードレビュアー）
- **推奨モデル**: `flash`
- **書き込み/MCP**: なし（`enable_write_tools: false`, `enable_mcp_tools: false`）
- **役割**: PR作成前の必須レビュー、セキュリティチェック。
- **システムプロンプトの指示**: `security.md` を基準にし、指摘事項は重大度・ファイル行番号・修正提案の形式で報告する。

### ✅ tester（テストランナー）
- **推奨モデル**: `flash`
- **書き込み/MCP**: 書き込みのみあり（テスト実行とログ出力のため）、MCP不要。
- **役割**: テスト実行、結果分析。
- **システムプロンプトの指示**: `Makefile` のコマンドを使用し、結果を構造化して報告する。

### 📝 planner（設計アドバイザー）
- **推奨モデル**: `inherit`
- **書き込み/MCP**: なし
- **役割**: 設計方針の立案、技術選定、タスク分解。
- **システムプロンプトの指示**: プロジェクト技術スタックを前提とし、複数の案を比較して提示する。

## 2. 運用ルール（オーケストレーション）

- **再利用とリソース解放**:
  新しいサブエージェントを呼ぶ前に `manage_subagents` (list) で idle 状態の同種エージェントを探して再利用する。目的が達成されたら速やかに `manage_subagents` (kill) で解放する。
- **モデル選択**:
  迷ったら `flash` を試し、不十分な場合のみエスカレーションする。`pro` はユーザー明示時のみ。
- **ワークスペース**:
  原則 `Workspace: 'inherit'`。破壊的テストが必要な場合のみ `'branch'`。
- **標準的な開発フロー**:
  作業着手時は必ず以下の手順を遵守すること。
  1. (親エージェント) **Issue起票**: 対応方針を含めてIssueを作成する。
  2. (親エージェント) **ブランチ作成**: `main` を最新化（pull）してから作業用ブランチを切る。
  3. (サブエージェント群) **新規ブランチで作業**:
     - researcher (flash) → 事前調査
     - planner (inherit) → 設計方針（必要な場合）
     - worker (inherit) → 実装・テスト作成
     - tester (flash) → テスト実行（失敗時は worker へ）
  4. (reviewer) **対応内容のレビュー**: PR作成前の必須レビュー（指摘時は worker へ）。
  5. (親エージェント) **PR作成**: レビューをパスしたらPRを作成する。
